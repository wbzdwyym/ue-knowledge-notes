# 性能：容器用法与位编码

这一类是"微观性能"：不改架构，换写法就能省掉一次拷贝、几条指令、一大截内存。

## 结论先行

1. **往 `TArray` 里加元素并马上填字段** → 用 `AddZeroed_GetRef()` / `AddDefaulted_GetRef()`，接收返回值必须是**引用**。这省掉的是"栈上先造临时对象 + 整结构体拷贝进数组"这一整趟。
2. **给"固定 2^n 个子项"编号** → 用位编码而不是查表/分支。3-bit 编码 `Index = (X<<0)|(Y<<1)|(Z<<2)` 让编解码 O(1)、遍历顺序天然等于空间顺序、还能被 SIMD 批处理。
3. 两篇都在演示同一件事：**性能来自把"运行时决策"前移到"编码/布局"里**。位编码把"8 个子节点谁是谁"编进了地址；`AddZeroed_GetRef` 把"构造在哪"编进了 API 形状。

## 怎么选

- **"我刚 `Add` 了一个元素，马上要填它的字段"** → 直接看 `tarray-add-zeroed-getref.md`，这是能立刻改掉的写法问题。
- **"我要表示一组固定数量的子项，而且频繁遍历/编解码"** → 看 `octree-3bit-index.md`；判据是"子项数量是 2 的幂、且每一项的身份能由几个二进制维度拼出来"。

> 别把这两篇当"优化清单"照抄。`AddZeroed_GetRef` 只在"新增 + 立刻填"时更优；位编码只在"子项数量固定为 2^n 且遍历频繁"时才值得。**先确认这里是热点，再换写法。**
