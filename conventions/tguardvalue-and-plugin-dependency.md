# TGuardValue 自动标记与插件单向依赖规范

## 一、函数内自动标记：`TGuardValue<bool>`

### 1.1 用途

在函数执行期间需要**临时**把某个布尔状态设为「进行中 / 已占用」（例如 `bIsCastingSkill`），并在**任意退出路径**（正常返回、`return` 早退、异常）上**自动恢复**进入函数前的旧值。避免手写多路 `if` 里反复赋值，减少漏恢复导致的粘滞状态。

### 1.2 典型写法（备份旧值并强制为 true）

```cpp
// 备份旧值，作用域内强制为 true；离开作用域（含早退）自动还原
TGuardValue<bool> CastGuard(bIsCastingSkill, true);

// ... 本段逻辑内其它代码可读 bIsCastingSkill == true ...
```

语义说明：

- **进入作用域**：`bIsCastingSkill` 被设为 `true`（或你传入的第二个参数）；析构时恢复进入前的值。
- 若进入前本来就是 `true`，结束后仍是 `true`，不会误清。
- 若需要「仅在原为 false 时临时置 true」，仍可用同一模式；Guard 负责的是**成对**的保存/恢复，而不是「强制从 false 开始」的额外语义——若业务要求「嵌套调用时只最外层生效」，需在类型或封装层另行设计（例如用计数或栈），本文仅约定 Guard 的常规用法。

### 1.3 使用建议

- 将 `TGuardValue` 声明在**需要该标记的最小作用域**内（例如单个 `if` 块、`for` 单次迭代体），缩小「标记为真」的可见范围。
- 成员变量、静态标记、重入敏感逻辑：优先用 Guard 保证异常安全；复杂重入规则可在此基础上再包一层小函数或专用结构体。
- 头文件：`TGuardValue` 定义在 `Misc/ScopedSlowTask.h`（UE 公共头）；按项目现有包含习惯引入即可。

### 1.4 与手写对比

| 方式 | 优点 | 风险 |
|------|------|------|
| 手写 `Old = X; X = true;` + 多处 `X = Old` | 直观 | 早退/异常易漏恢复 |
| `TGuardValue<bool>` | RAII 自动恢复 | 需理解作用域边界 |

## 二、插件与主工程：单向依赖规则

### 2.1 依赖方向（只允许「从外到内」引用）

```
主工程 / 核心模块（Zoira 主目录 Source、共享运行时）
        ↑ 可被依赖
ZoiraGenesis（及同层「基础 GF」若项目约定归入此层）
        ↑ 可被依赖
其它 Game Feature 插件（如 ZoiraCenozoic 等）
```

约定：

1. **主工程**：不依赖具体业务 GF 插件的实现细节（不把某 GF 的类当硬依赖链路的中心）。共享能力放在主工程或独立底层模块。
2. **ZoiraGenesis**：**可以**依赖主工程（头文件、模块、`Zoira` 命名空间下的公共 API 等）。
3. **其它插件**：**可以**依赖 **Genesis** 与 **主工程**；**不应**出现「Genesis 依赖 Cenozoic」或「插件 A 与插件 B 互相引用」形成环。

### 2.2 目的

- 编译顺序与模块图清晰，避免循环依赖。
- 主工程与 Genesis 作为稳定「内层」，扩展玩法插件作为「外层」，便于单独开关、迁移与测试。

### 2.3 落地检查（团队可自行勾选）

- 在 `.Build.cs` 中：`Genesis` 的 `PublicDependencyModuleNames` / `PrivateDependencyModuleNames` 是否只指向主工程及引擎/通用第三方，而不指向其它 GF？
- 其它 GF 若需 UI、背包、通用流程等，是否通过 Genesis 或主工程暴露的接口获取，而不是直接 include 另一个 GF 的私有实现路径？

---

## 三、小结

- **自动标记**：用 `TGuardValue<bool>` 在函数（或块）作用域内临时改写布尔标记，保证退出时恢复，适合技能施放、UI 模态、重入保护等场景。
- **依赖**：**主工程 ← Genesis ← 其它插件**，单向依赖，禁止跨插件环与「主工程依赖具体 GF」的硬耦合。
