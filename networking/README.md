# 网络：物理与逻辑的隔离、位数组过滤

这一类只抽一个思想：**把"混沌的底层状态"挡在门外，让业务代码只在干净数据上跑。** Iris 用它处理丢包乱序，`decoupled-polling-bitarray.md` 把它抽象成可以直接抄的通用模板。

## 结论先行

1. **Iris 的分层不是"为了模块化"，是为了隔离抖动**：底层 `Heartbeat & Tick` 负责守望连接、处理超时与断线（混沌）；高层 `UpdateDataStreams` 只在"确认还活着"的流上跑，遍历用 `FNetBitArray` 位图批量过滤（纯粹）。
2. 同一套结构可以脱离网络使用：**底层守卫负责防抖与裁决 → 产出一份权威位图/花名册 → 业务执行器只遍历位图里的 1**。这就是 `decoupled-polling-bitarray.md` 的两层隔离。
3. 判据：**只要你的轮询里混着"这个对象还在不在/要不要跳过"的判断，就该分层**——把判断收到守卫层，执行层只剩"对每个有效项做一件事"。

## 结构对照

```mermaid
flowchart LR
    subgraph 混沌层
        A["连接/对象原始状态<br/>丢包、乱序、超时、增删"] --> B["守卫：防抖 + 裁决"]
    end
    B --> C["权威位图 / 花名册<br/>（只有 0/1 是确定的）"]
    subgraph 纯粹层
        C --> D["执行器：只遍历 1<br/>不再判断有效性"]
    end
    D --> E["业务结果：复制、同步、更新"]
```

> 记住这条：**不要在两个地方各判断一次同一个"有效性"**。判断只允许发生在守卫层，执行层如果还要 `if (IsValid())`，说明位图没做干净。
