# ue-knowledge-notes

零散知识点的归档仓库：**一个话题一个文件夹**，每篇都要求「结论先行 → 机制拆解 → 能跑的代码 → 坑」。

姊妹仓库：[ue-navmesh-notes](https://github.com/wbzdwyym/ue-navmesh-notes)（专讲寻路）。本仓装其它主题。

## 目录

| 文件夹 | 主题 | 一句话 |
|---|---|---|
| [abstraction](./abstraction/) | 抽象 / 类型擦除 / 类型标签 | 用函数指针当类型标签，让公共模块永远不必依赖具体插件 |
| [architecture](./architecture/) | 架构：Impl/Pimpl、配置驱动、const | 延迟决定：实现延迟到 cpp、类型延迟到配置、可变性延迟到初始化完成 |
| [concurrency](./concurrency/) | 并发：读写分离 / RCU / 双缓冲 / 共享切片 | 别让同一份可变数据被多方访问，让访问方各持一份不可变的东西 |
| [performance](./performance/) | 性能：容器用法与位编码 | 把运行时决策前移进编码与内存布局 |
| [networking](./networking/) | 网络：物理与逻辑隔离、位数组过滤 | 混沌挡在守卫层，执行层只遍历确定有效的那批 |
| [conventions](./conventions/) | 规约：编译期裁剪、状态恢复、依赖方向 | 代价延迟出现：打包版、专用服务器、两个月后的模块边界 |

每个文件夹的 `README.md` 是**该主题的判据与索引**（什么时候该翻哪篇、怎么选、三条最常被违反的），单篇文档不要求先读别的篇。

## 两类内容

| 类型 | 位置 | 标准 |
|---|---|---|
| **自写笔记** | `abstraction/` | 按「结论先行 → 机制拆解 → 能跑的代码 → 坑」写；代码分**可编译验证**与**参考实现**两类并标注 |
| **规约原文归档** | `architecture/`、`concurrency/`、`performance/`、`networking/`、`conventions/` | 内部开发规约的原文，**内容保持原样**（只重命名文件、补分类索引）。原文文件名与仓库文件名的对应关系写在各自分类的 README 表格里 |

## 约定

- 每篇文档自带结论与判据表，不要求读者先读别的篇。
- 代码分两类，明确标注：
  - **可编译验证**（纯 C++ / 纯数据，本机编译并跑过输出）；
  - **参考实现**（依赖 UE 类型，只能贴不能直接编译）。
- 文档里引用引擎源码时给到 `文件:行号`，给不出证据的一律标注为「未核实」。
